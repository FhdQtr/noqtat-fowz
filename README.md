# الميدان | الميدان يا حميدان

منصة مسابقات عربية مباشرة للمجالس والتجمعات. يدير المقدم الميدان، وتدخل الفرق من جوالاتها بأكواد مستقلة، وتظهر الأسئلة والنتائج على شاشة الجمهور.

## المزايا

- من فريقين إلى أربعة فرق، مع قائد اختياري لكل فريق.
- أكثر من ١٠٠٠ سؤال مفعّل في ١٠ أنواع بنكية؛ والإعداد يعرض ١١ خياراً بإضافة «سؤال وعقاب» الذي يكتبه المنافس. الصعوبة غير متدرجة تلقائياً؛ قيمة تكرار القسم ليست تصنيف صعوبة.
- شاشة مقدم، شاشة جمهور، وجوالات اللاعبين متزامنة لحظياً.
- أسئلة صور وذاكرة وأعلام وتمثيل، مع السرقة والمساعدة. الفيديو مدعوم في الأسئلة المخصصة، ولا توجد أسئلة فيديو مضمّنة مفعّلة.
- «ساحة الحسم» تلقائياً عند تعادل المتصدرين.
- ست بطاقات تكتيكية لكل فريق: وقت إضافي، تبديل السؤال، اختيار اللاعب، مضاعفة النقاط، تجميد الكروت، والسرقة. لها رصيد مكتسب مستقل عن نقاط الفوز وأسعار تعتمد طول المباراة.
- تحدي فردي من ١٠٠ سؤال عشوائي بإجابات محفوظة على الخادم؛ تستبعد الذاكرة حتى تدعم مرحلتي المشاهدة والإخفاء. ليس ترتيباً تنافسياً موثقاً خادمياً.
- بنك خاص للمقدم، استيراد جماعي، ونسخ احتياطي.
- هوية «الميدان» وأيقونات أصلية مصممة خصيصاً للمشروع.

## التقنية

- React 19 + TypeScript + Vite 7
- Tailwind CSS 3.4
- Firebase Authentication + Realtime Database + Cloud Functions v2
- تحميل كسول لكل شاشة لتقليل حجم البداية

## التشغيل محلياً

محلياً ومعاينات Vercel غير الرسمية تعمل افتراضياً بلا اتصال ببيانات اللعب. إعداد الميدان قابل للمعاينة، لكن إنشاء الغرف يتطلب بيئة اختبار منفصلة. لا تُستخدم بيانات الإنتاج تلقائياً. تفاصيل المحاكي والتوافق وحدود هذا الإصلاح في [ملاحظات التطوير](docs/development-checkpoint2.md).

```bash
npm ci --ignore-scripts
npm run dev
```

لفحص بنك الأسئلة وبناء نسخة الإنتاج:

```bash
npm run check
```

## الأمان وFirebase

النسخة على الفرع التطويري ليست إصداراً منشوراً. نشر Vercel لا ينشر وظائف Firebase أو القواعد أو البنك. يجب اعتماد خطة توافق مستقلة قبل أي نشر إنتاجي؛ الأجوبة العادية الجديدة تحتاج questionId وattemptId وrevision وrequestId، وأفعال المقدم للكشف والحكم والنقل والانتقال تحتاج سياق transition من الحالة المعروضة مع هوية طلب ثابتة عند إعادة الإرسال. التخطي الصريح يبقى بيد المقدم. تفاصيل وحدود الانتقالات العادية في [checkpoint5](docs/development-checkpoint5.md). اختيار القسم يحتاج أيضاً transition ثابتاً من شاشة الفريق؛ نشر السؤال والتبديل والمواجهة يربط سراً خاصاً ذا نسخة بمعاملة مشروطة، ولا يعني اكتمال ذرية سجل الدوران أو استرداد كل البطاقات. راجع [checkpoint6](docs/development-checkpoint6.md) ثم [checkpoint7](docs/development-checkpoint7.md) قبل النشر: الاختيار والتبديل والمواجهة البنكية تحجز مخزونًا مؤقتًا، ولا تستهلكه إلا بإيصال نشر دائم قابل للتسوية بعد الانقطاع؛ هذا ليس معاملة ذرية واحدة لكل الأشجار ولا حجزًا لسعة مسابقة كاملة. البطاقات تحتاج سياق الشاشة، ولها مهلة ملكية تنفيذ وإيصال نجاح لإعادة الطلب نفسها. سعة الحسم/النفاد والتنظيف والتوافق النهائي ما زالت بوابات إصدار مفتوحة. لا تنشر الوظائف الجديدة وحدها أمام عملاء قدامى دون خطة تحديث/صيانة.

راجع أيضًا [checkpoint8](docs/development-checkpoint8.md): عند نفاد المخزون تظهر حالة توقف واضحة للمقدم والفرق والتلفزيون مع إعادة فحص مشروطة لا تمسح التاريخ. الأقسام المنتهية لا تقفل دورة الأقسام الأخرى؛ والحجز المؤقت ليس نفادًا دائمًا. هذه ليست ضمانة حجز سعة مسابقة كاملة أو حسم محدود؛ بوابات الإصدار المتبقية موثقة.

المؤقت العادي إرشادي: لا يقفل الجواب عند الصفر، ويبقى الحكم للمقدم. مؤقت مواجهة الجميع له نافذة وصول خادمية ملزمة. لا تغير نقاط الفوز أو اقتصاد البطاقات في هذا الإصلاح.

التغييرات الحساسة لا تُكتب من المتصفح. إنشاء الغرفة، اختيار السؤال، تثبيت الإجابة، احتساب النقاط، والحسم تنفذها Cloud Function وتتحقق من هوية المقدم واللاعب. الإجابة الصحيحة تحفظ في `matchSecrets` ولا تظهر في حالة المباراة العامة قبل حسمها.

1. فعّل Anonymous وEmail/Password من Firebase Authentication.
2. ثبّت Firebase CLI وسجّل الدخول إلى مشروع `noqtat-fowz-d13aa`.
3. ثبّت حزم الوظائف:

```bash
cd functions
npm install
cd ..
```

4. انشر الوظائف والقواعد والاستضافة:

```bash
npm run build
firebase deploy --only functions,database,hosting
```

ينسخ `firebase.json` بنك الأسئلة إلى حزمة الوظائف آلياً قبل النشر. لا تنشر `database.rules.json` وحده قبل نشر الوظيفة، لأن القواعد تمنع أي كتابة مباشرة من المتصفح.

## حساب المدير

أنشئ حساب Email/Password للمدير من Firebase Console، ثم امنحه custom claim باسم `admin` باستخدام بيانات خدمة Firebase/ADC:

```bash
cd functions
npm run set-admin -- admin@example.com
```

بعدها يسجل المدير من `/admin`. بنك الأسئلة المخصص لا يمكن قراءته أو تعديله إلا بحساب يحمل صلاحية `admin`.

## App Check

1. سجّل تطبيق الويب في Firebase App Check باستخدام reCAPTCHA Enterprise.
2. أضف مفتاح الموقع العام في Vercel باسم `VITE_FIREBASE_APP_CHECK_SITE_KEY` ثم أعد نشر الواجهة.
3. راقب طلبات App Check في Firebase وتأكد أن الأجهزة الحقيقية تستقبل رموزاً صالحة.
4. اضبط متغير بيئة الوظائف `ENFORCE_APP_CHECK=true` ثم أعد نشر الوظائف. لا تفعّل هذا المتغير قبل نشر الواجهة بالمفتاح، وإلا ستُرفض طلبات اللعب.

رمز شاشة الجمهور يبقى أربع خانات ليسهل إدخاله. دخول الفرق يستخدم مفتاح دعوة مستقل داخل QR، ويُغلق تلقائياً عند بدء المسابقة.
