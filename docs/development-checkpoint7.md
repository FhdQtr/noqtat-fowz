## Implemented contract

Bank-backed ordinary selection, swap and classic showdown now reserve inventory privately in `questionRotation/HOST/pending`. Pending holds exclude the asset and its semantic/image aliases from competing draws across that host's rooms. They DO NOT create/age a consumed game or advance section usage. The immutable shuffled question, aliases, section generation and 30-second expiration are stored in the reservation.

A guarded room transaction publishes both the question/effects and an opaque `rotationPublications/UUID = published` receipt. No private answer, choice mapping or alias hash is added to public state by this protocol. The private secret version uses the reservation's publication UUID, so concurrent retry preparation of the same bank draw writes the same immutable secret instead of producing arbitrary additional versions. The public receipt contains only an opaque UUID and status.

Reconciliation finalizes the host ledger only from durable room receipts. A crash after the public commit but before ledger finalization is recovered by a subsequent draw or create/start preflight. Concurrent finalizers compare the reservation generation; they cannot finalize twice or erase a newer recovery generation. Already-finalized request receipts preserve the same shuffled result and publication identity.

An expired/unpublished or ended-room reservation is fenced with `cancelled` in a room transaction BEFORE its inventory is released. Every relevant publisher checks expiration and the cancellation fence in its committing transaction. A delayed executor therefore cannot publish an asset after another selection has reclaimed it. A retry of an expired unshown request gets a fresh publication generation. This is a recoverable cross-tree protocol, NOT a single database-wide atomic transaction. The decisive consumed event is the public room commit, not the lobby, reservation, received answer or eventual finish. It counts a question shown even if nobody answers it.

Legacy15 records and undated separate flags remain preserved. Pending migration persists the conservative synthetic legacy-flag recent-game record, and finalization retains valid section usage. No live migration was executed. Ordinary direct helper calls without a publication room retain immediate-consumption semantics for existing offline fixtures; all three runtime bank-selection callers use the pending/publication path. Picture guessing and player-authored punishment are not bank-backed draws and do not gain bank history by implication.

Temporary holds that are the only obstacle return retryable `unavailable`/busy rather than permanent rotation exhaustion. They do not mark a section permanently blocked. Capacity inspection itself stays no-write and conservative; explicit create/start reconciliation first recovers stale holds. This does NOT reserve a whole competition's future inventory against another simultaneous competition.

## Cards

All six card commands require captured displayed phase/question/round/attempt/revision and a request ID. A fingerprint binds actor, team, card and selected player as well as the context. A bounded last-success receipt returns the identical accepted result after response loss, without a second spend or allowing changed parameters. It is not an unlimited historical receipt service.

A whole-room transaction owns a unique 30-second card executor lease separate from the displayed selection/attempt. Live ownership is busy; expired new-format ownership is recoverable. Commit checks current context, membership, claim/lease, balance, card availability and timing. Release only removes its own ownership. Existing unversioned legacy card claims remain fail-closed; drain old games before release rather than guessing their expiry. Frontend freezes one card payload for a single transport retry and passes the actual displayed match. Card prices, scoring and intentional presenter adjudication remain unchanged.
